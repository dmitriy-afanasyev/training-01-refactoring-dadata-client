# Тестовое задание: Рефакторинг DaData API Client

## 📋 Контекст

В папке `before/` находится код для работы с DaData API (https://dadata.ru/api/).

Один контроллер, который полностью нерабочий, нарушает SOLID, не имеет тестов и требует серьёзного рефакторинга.

## 🎯 Задачи

1. Сделать код рабочим
2. Поднять Docker-контейнер с **PHP 8.5**
3. Провести рефакторинг
4. Написать тесты

## 📖 Формат

Это задание можно рассматривать в двух форматах:

- **Тестовое** — выполнить требования и получить рабочее решение
- **Тренировочное** — изучить/применить/попрактиковать различные архитектурные подходы к одной задаче

Каждое решение в папке `after/` — это самостоятельная реализация со своей архитектурой. Где-то мы делаем больше, чем могло бы понадобиться в реальном решении тестового задания — ради обучения и следования лучшим практикам. Где-то намеренно не делаем лишнего — чтобы показать минималистичный подход.

## ✅ Что нужно сделать

### 1. Сделать код рабочим

- Исправить синтаксические ошибки
- Добавить недостающие зависимости

### 2. Docker-окружение

- PHP 8.5 FPM
- Возможность запуска тестов

### 3. Рефакторинг

- Разделить ответственность (SRP)
- Добавить строгую типизацию (PHP 8.5)
- Вынести API-ключ в переменные окружения
- Добавить обработку ошибок

### 4. Тестирование

- Написать юнит-тесты
- Достичь покрытия > 80%

## 📦 Ожидаемый результат

- Рабочий код в папке `after/`
- Docker Compose для запуска
- Тесты, проходящие успешно

## ⏱️ Ограничения

- API-ключ должен храниться в `.env`
- Можно использовать любые библиотеки (Laravel, Guzzle и т.д.)
- Нет жёстких ограничений на архитектуру — это часть тренировочного формата

## ⚠️ Обрати внимание

Условия задачи сформулированы намеренно размыто — где-то конкретно, где-то обобщённо. Если рассматривать задание как тестовое, это сделано умышленно: чтобы спровоцировать соискателя задавать уточняющие вопросы.
