# О нарушении SRP в `AddressService`

Может показаться, что `AddressService` нарушает **SRP** (принцип единственной ответственности), особенно на фоне рядом расположенных служб `BankService` и `PartyService`.

Однако здесь нет классического нарушения **SRP** – это **группировка по домену, а не по операциям**.  
Согласно принципу:

> _«У класса должна быть одна причина для изменения»_.

В данном случае причина только одна – **изменение логики поиска адресов**.

---

### Когда стоит задуматься о разделении?

Если в будущем функционал начнёт разрастаться, например:

1. Метод `searchCountry` начнёт возвращать отдельный DTO (вместо простого результата).
2. Появятся отдельные методы `suggestCountry`, `getCountryDetails` и т.п.

Тогда можно будет разделить функциональность на несколько классов.
